# ระบบแนะนำอนิเมะตามความสนใจ

เข้าเมนู **แนะนำสำหรับคุณ** หรือ `/me/recommendations` หลังเข้าสู่ระบบ เพิ่มเรื่องในรายการอยากดูหรือให้คะแนนในหน้ารายละเอียด แล้วกลับมาหน้านี้เพื่อดูผลที่คำนวณใหม่ ปุ่ม **อัปเดตคำแนะนำ** อ่านข้อมูลล่าสุดโดยไม่ต้องโหลดหน้าเว็บใหม่

## ต่อยอดจากสิ่งที่เรียนอย่างไร

| ความรู้เดิม | สิ่งที่นำมาต่อยอด |
|---|---|
| React hooks และการเรียก API | รวมสถานะ loading/error/empty, retry และแสดงเหตุผลของข้อมูลที่ server คัดมา; ไม่ให้ผลตอบกลับเก่าทับข้อมูลเมื่อเปลี่ยนบัญชี |
| การออกแบบ API และ authentication | เพิ่ม `GET /api/me/recommendations`; ใช้ member จาก token ที่ตรวจสอบแล้ว ไม่รับ memberId จากหน้าเว็บ |
| SQL, JOIN และ aggregate | เชื่อม `anime`, `wishlist_items`, `votes`; แตกแนวด้วย `unnest`, รวมสัญญาณด้วย `UNION ALL` และสรุปน้ำหนักด้วย `GROUP BY` |
| เงื่อนไขและการเรียงลำดับ | เขียนกติกาคะแนน แยกสมาชิกใหม่ จัดการคะแนนที่ไม่มีข้อมูล และตัดเรื่องที่รู้จักแล้ว |
| การทดสอบ | ตรวจผลลัพธ์จริงผ่าน HTTP และ PostgreSQL รวมถึงการแยกบัญชี แก้คะแนน ลบสัญญาณ และกรณีไม่มีเรื่องใหม่ |

เป็นระบบแนะนำตามเนื้อหาแบบใช้กติกาถ่วงน้ำหนักที่อธิบายได้ ไม่ได้ฝึกโมเดล machine learning และไม่มีการส่งข้อมูลความชอบไปยังบริการ AI ภายนอก

## กติกาคะแนน

| การกระทำของสมาชิก | น้ำหนักต่อแนวของเรื่องนั้น |
|---|---|
| เพิ่มในรายการอยากดู | +1 |
| ให้คะแนน 8–10 | +3 |
| ให้คะแนน 5–7 | 0 |
| ให้คะแนน 1–4 | -2 |

- สัญญาณในรายการอยากดูและคะแนนบวกกันได้ เช่น เรื่องเดียวกันอยู่ในรายการและได้ 9 คะแนน จะเพิ่ม +4 ต่อแนว
- นับแต่ละแนวของเรื่องหนึ่งครั้ง แม้ข้อมูลจะมีแนวซ้ำ
- รวมทุกสัญญาณของบัญชีเป็นน้ำหนักสุทธิของแต่ละแนว หน้าเว็บแสดง 5 แนวน้ำหนักบวกสูงสุด
- ไม่แนะนำเรื่องที่สมาชิกเก็บในรายการหรือให้คะแนนแล้ว ไม่ว่าคะแนนจะสูงหรือต่ำ
- คะแนนความสนใจของเรื่องใหม่ = ผลรวมของน้ำหนักแนวที่ตรงกัน รวมแนวที่มีน้ำหนักลบด้วย
- แนะนำเรื่องที่คะแนนความสนใจ >0 ก่อน เรียงคะแนนความสนใจมากไปน้อย แล้วใช้คะแนน MAL, ชื่อ และ ID ตัดสินเมื่อคะแนนเท่ากัน ส่งกลับไม่เกิน 12 เรื่อง
- `matchedGenres` ใช้เฉพาะแนวน้ำหนักบวกที่ตรงกัน จึงไม่บอกว่าแนะนำเพราะแนวที่ผู้ใช้ไม่ชอบ
- เมื่อไม่มีเรื่องใหม่ที่คะแนนความสนใจเป็นบวก ใช้โหมดเริ่มสำรวจจาก MAL เฉพาะเรื่องที่คะแนนความสนใจ >=0 โดยไม่กล่าวอ้างว่าตรงกับรสนิยมส่วนตัว; เรื่องที่ไม่มีคะแนน MAL อยู่ท้ายรายการ
- ถ้าไม่มีเรื่องที่ผ่านเงื่อนไข ส่งรายการว่างให้ UI อธิบาย ไม่วนกลับไปแนะนำเรื่องเดิม

คะแนนความสนใจเป็นคะแนนภายในเพื่อเรียงลำดับ ไม่ใช่คะแนนรีวิวหรือเปอร์เซ็นต์โอกาสที่สมาชิกจะชอบเรื่องนั้น

## ตัวอย่างที่อธิบายบนสไลด์ได้

สมาชิกเก็บเรื่องแนว Fantasy ไว้ และให้เรื่องนั้น 9 คะแนน จากนั้นให้เรื่องแนว Action 8 คะแนน และเรื่องแนว Drama 2 คะแนน

| แนว | น้ำหนักสุทธิ |
|---|---|
| Fantasy | 1 + 3 = 4 |
| Action | 3 |
| Drama | -2 |

| เรื่องใหม่ | แนว | คะแนนความสนใจ |
|---|---|---|
| เรื่อง A | Fantasy | 4 |
| เรื่อง B | Action | 3 |
| เรื่อง C | Fantasy, Drama | 4 - 2 = 2 |

ลำดับคือ A → B → C แม้ B จะมีคะแนน MAL สูงกว่า A เพราะความสนใจส่วนบุคคลมาก่อนคะแนนต้นทาง หาก A และอีกเรื่องได้ 4 เท่ากัน จึงใช้ MAL ตัดสินลำดับ

## แผนสาธิตประมาณ 2 นาที

1. สมัครสมาชิกใหม่ แล้วเปิด **แนะนำสำหรับคุณ** ให้เห็นข้อความว่าเริ่มต้นจากคะแนน MAL
2. เลือกอนิเมะในแนวที่มีเรื่องอื่นอยู่ในคลัง เช่น Fantasy เพิ่มรายการอยากดู แล้วกลับมาดูแนวความสนใจและข้อความ **เพราะคุณสนใจ แฟนตาซี** บนเรื่องใหม่
3. ให้คะแนน 8–10 กับอีกแนว เช่น Action แล้วกด **อัปเดตคำแนะนำ** เพื่ออธิบายว่าคะแนนสูงมีน้ำหนักมากกว่ารายการอยากดู
4. แก้คะแนนเป็น 1–4 หรือยกเลิกคะแนน กลับมาดูผลใหม่ แล้วชี้ว่าตัวระบบอ่านข้อมูลล่าสุด ไม่เก็บผลเดิมค้างไว้
5. เปิดบัญชีอีกคนหรือสมาชิกใหม่เพื่อแสดงว่าความสนใจแยกกัน และชี้ว่าเรื่องที่เก็บ/ให้คะแนนแล้วไม่กลับมาเป็นเรื่องแนะนำ

ข้อความตัวอย่างสำหรับปรับเป็นคำอธิบายของผู้เรียน:

> นำ React, API และ SQL มาต่อยอดจากเว็บแสดงรายการ เป็นระบบแนะนำอนิเมะที่ใช้ข้อมูลความสนใจของแต่ละสมาชิก โดยเขียนกติกาคะแนนเองและแสดงเหตุผลของคำแนะนำ สามารถอธิบายได้ว่าการเปลี่ยนคะแนนหรือรายการอยากดูส่งผลต่ออันดับอย่างไร

ใช้คำอธิบายเฉพาะส่วนที่เข้าใจและสาธิตได้จริง พร้อมระบุเครื่องมือช่วยพัฒนาตามข้อกำหนดรายวิชา

## จุดสำคัญในโค้ด

- [backend/store/recommendations.go](../backend/store/recommendations.go): CTE สัญญาณ น้ำหนัก แนวที่ตรงกัน และอันดับ
- [backend/handler/recommendations.go](../backend/handler/recommendations.go): เลือกบัญชีจาก middleware และตอบ `Cache-Control: no-store`

- [backend/handler/recommendations_test.go](../backend/handler/recommendations_test.go): ทดสอบ HTTP + PostgreSQL จริง โดยใช้ schema ชั่วคราว
- [frontend/src/pages/Recommendations.test.jsx](../frontend/src/pages/Recommendations.test.jsx): เหตุผล สมาชิกใหม่ การลองใหม่ อัปเดตผล เปลี่ยนบัญชี และ guest redirect

## ทดสอบ

```bash
cd frontend
CI=true npm test -- --watchAll=false --runInBand
npm run build
```

```bash
cd backend
# ตั้ง TEST_DATABASE_URL ไปยังฐานข้อมูลทดสอบของคุณก่อน
go test ./... -v -count=1
```

เมื่อไม่มี `TEST_DATABASE_URL` การทดสอบที่ต้องใช้ฐานข้อมูลจะถูก skip. ใช้ schema ชั่วคราวที่สร้างและลบเองในฐานข้อมูลทดสอบ ไม่ใช้ข้อมูลสมาชิกจริง

## ขอบเขตของรุ่นนี้

ใช้แนวอนิเมะ รายการอยากดู และคะแนนเท่านั้น ไม่วิเคราะห์ข้อความรีวิวหรือประวัติการคลิก สมาชิกที่มีความชอบคล้ายกันอาจได้รับเรื่องแนะนำเหมือนกัน และจำนวน/ความหลากหลายของอนิเมะในคลังมีผลต่อผลลัพธ์ ไม่มีตารางความคืบหน้าการดู จึงไม่อ้างว่ารู้ว่าเรื่องใดดูจบแล้วนอกเหนือจากเรื่องที่ให้คะแนน
